# 現勘紀錄與交接規則

這是空白表與填寫方法，不是現場結果。先用`planned-visits.csv`排真實日期與觀察組，再逐次記錄。市區216筆、校區18筆均為未執行；實際量測欄保持空白。

## 一次訪次的操作

1. **確認範圍。** 使用`anchor-scope-setup.csv`逐點記錄錨點ID、固定街段兩端地標、側別、安全站位、拍攝方向、服務點清單和`route_version`。錨點站座標是查核入口，不是垃圾桶或已核准站位；第一次現勘先確認範圍。不同範圍的計數不能直接相減。
2. **分開紀錄。** A記錄15分鐘內直接看到的投放行為；B記錄服務點、路徑、街面起末存量及清掃時間。B的前後盤點可超過15分鐘，另記實際時間，不冒充A的行為觀察窗。兩人不是兩個獨立樣本。
3. **保存原始值。** 觀察中斷便記有效分鐘、原因和訪次狀態。不把預定15分鐘填成實際時長，不將部分時長外推成完整15分鐘。只有確實完整觀察且事件未發生才能填0。
4. **逐桶記錄。** 每個實際查到的服務點各一列，使用同一visit_id及service_point_id。找不到來源紀錄時寫「未找到／待確認」，不推定現場零桶。
5. **複核交接。** 核對日期日型、時窗、事件分項、服務點數、原始照片編號與未知原因；複核者填代碼。保留取消及補訪原紀錄。

## 訪次表欄位

| 欄位 | 意義與填寫規則 |
|---|---|
| visit_id | 錨點ID－日槽－對照／活動窗；補訪另加R1等尾碼，原紀錄不刪除 |
| day_slot／day_type | WD1及WD2須不同平日；WE1為週末；實際日期依Asia/Taipei核對 |
| allowed_window／suggested_start／suggested_end | 來源小時窗與排程提案，不是已到場的起迄 |
| actual_date／team | 實際日期及組別代碼；公開版不放姓名或聯絡資訊 |
| actual_start／actual_end／effective_minutes | 真實起迄與有效行為觀察分鐘；中斷扣除並記原因 |
| status | 未排日期、已排待查、完成、部分完成、取消、改期、不適用；不可用「完成」掩蓋缺測 |
| route_version／weather／site_changes | 固定範圍版本、天候、施工或活動等脈絡；變更須可追溯 |
| litter_start_count／litter_end_count | 同固定範圍盤點的可逐件辨識散落物存量；起末差不能直接當新增丟棄量，清掃與移動可能影響 |
| observed_disposal_attempts | 直接看見的自然投放嘗試；不推定看不到的事件或人的動機 |
| observed_successes | 直接看見完成投放的嘗試 |
| observed_blocked_attempts | 直接看見受阻或放棄的嘗試；另寫可觀察到的狀況，不猜原因 |
| observed_unresolved_attempts | 看見嘗試但結果未能辨識；三類分項之和等於已辨識的嘗試總數，缺測者留空 |
| collection_event | 看見清空或掃街的時間及服務點；沒看到不代表未清運，未知照填 |
| service_point_record_ids | 本訪次逐服務點附表列ID；數量不限，不因表格空間省略 |
| reason_or_deviation／reviewer | 缺測、偏離、取消、改期或不適用原因；複核者代碼 |

## 逐服務點附表

`service-point-records.csv`是只有欄名的空白表；每次查到幾個服務點就新增幾列。ID可用「D01-1-B01」；每個訪次另外記一列以保留時間變化。

- `status`：已核實可用、已核實不可用、未找到來源紀錄、未能確認。來源線索與現場核實結果分開。
- `fill_level`：empty、1_25、26_50、51_75、76_99、full_no_overflow、overflow、unknown。只按可看見的狀況，不打開或接觸垃圾。
- `start_litter_count`／`end_litter_count`：同一預先界定的周邊範圍內存量；堆置無法逐件數時在備註說明，不能估成件數。
- `walking_route`：記實際出入口、過街、障礙與替代服務；未走過就寫待查。直線距離不可替代步行距離。
- `last_confirmed_clearance`／`source`：能確認才填；口述或現場公告要標來源，無證據不填時間。
- `manager`／`authority_status`：已核對的管理單位及依據，否則待核實；不以站名或行政區推定土地權屬。
- `photo_ref`：用檔案編號連結現場景物，不收集路人身分與聯絡資訊；避免清晰人臉、車牌及非必要私人資訊。

## 判讀與下一步

| 證據情形 | 可以交付的判讀 | 下一步 |
|---|---|---|
| 清冊、範圍或量測不足 | 資料不足，保留未知與缺測 | 補件／補訪，不推論零需求 |
| 已有可用設施，但實際路徑、指引或辨識受阻 | 資訊／可達性問題線索 | 檢查B原位指引是否值得比較 |
| 箱體不可用、滿溢或清運條件有直接紀錄 | 維護／清運問題線索 | 交建議清潔服務窗口核對，不先加桶 |
| 有可比較基線、步行與權責資料，且其他改善不足 | 可進一步研究配置的候選 | 交C等總量位置調整比較，仍不是核准設點 |

四類可同時存在。沒有足夠證據時可交付維持現況或補查理由。各錨點邊界不同，不直接比較原始垃圾件數大小；沒有預先一致的面積、人流分母與可比觀測，就只作站內描述。此輪沒有介入前後對照，不報改善比例。

## 投放旅程與車籃事件附表（2026-10-22）

依PRD v0.5 R3／R4新增[四張空白表、欄位字典與12個驗收案例](field-record-forms.md)。表1記一段旅程的單一依據；表2A／2B記盤點及逐車籃狀態；表2C記遇見／處理，必要時連回表1的最後投放。同一投放只計一次，車籃存量與事件分開。

四份CSV在`templates/`，只有欄名，沒有實測列。先複製工作副本再填；網站只公開空白表與規則，不儲存或送出紀錄。既有234筆計畫訪次及逐設施表未改為已執行。

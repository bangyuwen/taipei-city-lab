## 計分與停止規則的演練案例

以下是主持人校準用的假設案例，不是實驗觀察或模擬受測者。正式判讀仍須滿足 README 的全部條件，不能只憑單一總分。

| 假設輸入 | 應採取的判讀／動作 |
|---|---|
| S1 在 45 秒選擇較遠但有效的 C，能指出相應路線，無提示 | 記正確；另記距離，不因未選最近的 B 判錯 |
| S3 揭露滿溢後 35 秒指出由 B 再走 140 公尺到 C，無提示 | 改道判斷可記正確；第一次到 B 的回答不混入這 35 秒 |
| S4 正確保留家戶垃圾並確認家戶服務 | 記安全停止／決策正確；實際投放仍不適用 |
| 30 秒時得到提示，45 秒答對 | 留原始 45 秒；獨立成功為否，比較用 60 秒 |
| M1 常見任務 22/24、M0 21/24，即使配對時間縮短 25% | 淨增益未達 3 次，且 M0 未達時間比較要求的 22/24；不滿足實用增益，不進現場 |
| 總平均達標，但 M1 先看組沒有正增益 | 順序影響未釐清，不宣稱有穩定增益 |
| 未招募、未開始或缺少需求配額 | 保持未開始／資料不足；空白不是零，也不是成功 |
| 參與者確認要使用已關閉點 | 立即停止該題並暫停本版；保留已收資料，不繼續湊 12 人 |
| 同一根因出現在第二位參與者 | 暫停本版；修改時建立新版新輪次，不合併前後結果 |
| 現場安全保留垃圾，但沒有實際被接收投放 | 安全停止可以記錄，真實投放成功為否 |

## 技術驗證與重製

以下技術驗證是 2026-10-18 在來源工作副本完成的歷史結果；移轉時沒有重跑。原型的 88 組情境、媒介、尺寸、明暗及文字一致性檢查曾通過。衍生材料也曾檢查手機卡、順序、PDF 文字與逐頁視覺；歷史摘要保存在 `validation.json`。這些技術檢查不是真人研究結果。

本輪結果：20 張有效手機卡、3 種無效／缺失卡輸入、26 頁主持表尺寸檢查皆通過，0 外部請求、0 腳本錯誤。獨立驗證者編寫檢查腳本，母代理執行需要本機瀏覽器的部分；驗證者另核對排程、空白狀態與 PDF 文字。母代理渲染全部 50 頁，目視檢查並修正總表截斷與例外框溢出。這只確認桌面 Chrome 的操作與列印，實體手機和真人理解仍須預試。

來源包的 `checks/` 腳本、瀏覽器記錄與逐頁檢查圖片不在這份可攜研究包內；`validation.json` 只保留歷史檢查摘要，不代表本工作樹已重跑或能從本包單獨重現檢查。檢查資料不併入研究分母。

`build-test-pack.cjs` 從 `source/prototype-v0.1.html` 產生手機卡、材料入口、空白預排與參與者 PDF；主持表是本輪保留的獨立輸入。需要 Node.js、Playwright 與可用的 Chromium 瀏覽器。若要指定瀏覽器執行檔，可設定 `CHROME_PATH`。在材料目錄執行：

```sh
node build-test-pack.cjs
```

來源工作副本的瀏覽器檢查封鎖網路請求。重製會覆寫同名衍生檔，只在未填入真人資料的材料工作副本執行。`inspect-pdf.py` 可將全部 PDF 頁面渲染到指定暫存目錄；此移轉保留原 PDF 位元組，沒有重製或重跑視覺檢查。`manifest.json` 列出這份可攜研究包保留檔案的指紋。

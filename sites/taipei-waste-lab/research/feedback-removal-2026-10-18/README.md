## 具體怎麼說，以及先查什麼

以下是逐則回讀後的改寫，不是逐字引文。例子說明機制，不代表該地多數人的看法，也不把一則留言中的後果套到其所有地名。

### 繞路：大安森林公園外圍

有留言描述外圍原有桶消失，遛狗、散步時須走進園內才能投放。另一則則說後來零星換回新桶，但擔心較大的開口招來家戶混投。

對應查核（尚未執行）：分開查園內與外圍、實際步行路線和桶口設計。園內有場域紀錄，仍不能證明外圍的便利性已恢復。

### 集中承壓：敦化南路與頂好市場

有留言希望恢復敦化南路部分桶位，並說剩下的頂好市場桶常滿，垃圾還會堆到地上。這指向替代點的負荷，而不只是一條路的桶數。

對應查核（尚未執行）：先定位市場桶在何處，再同時觀察周邊步行距離、尖峰容量及清運間隔；尚不能由留言證實撤桶造成滿溢。

### 有取捨：松江、南京路口

一則留言認為撤桶讓遛狗投放不便，也說夜間垃圾不再大量堆積。另有留言要求增加清運；不能把這些意見簡化成只有恢復原數量。

對應查核（尚未執行）：比較恢復或重配後的投放便利、混投與夜間堆積，再配合管理與清運觀察。

### 邊界不同：北投、南港的車站

北投有留言指定1號出口對面公園，也有留言提到車籃垃圾；南港則分別提到火車站前、轉運站和昆陽站。這些地點與垃圾去向不能合成一個站區問題。

對應查核（尚未執行）：把公園、台鐵站前、轉運站、捷運站內外分開查，沿實際路線確認可使用的投放點與管理機關。

## 下一步與目前缺口

- **補上可核對的地點與時間**：優先把站名補到出口與道路側，把公園補到內外圍、入口與路線；回查留言日期，再核對前後照片、桶號及撤移工單。這是資料查核順序，不是缺桶程度排名。
- **同時看原點、替代點與垃圾去向**：同一時段走過原路線，記錄距離、可見性、開放時間、桶滿程度及替代場所是否接受投放；分開觀察車籃、花圃與人行道垃圾，避免只移動問題。
- **依困難測試改善，保留管理條件**：確認路線缺口後才評估恢復或重配；替代點滿溢則檢查容量、巡收和混投；設備難用則查開口與操作。每項都需觀察改善前後，尚未執行或證明有效。

一般頁面重建在網站目錄執行 `python scripts/package-research.py`。只有持有完整私有封存資料並解壓後，才可執行下列分析重算；`/private/removal-coding` 是待替換的示例路徑：

```sh
python scripts/feedback_removal.py --private-dir /private/removal-coding
python scripts/package-research.py
```

一般建置只讀取保存的彙總與人工比對，不需要公開原文或重跑語意判讀。
